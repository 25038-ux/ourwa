# Audit de parité — El Ourwa **v23** contre le dépôt, page par page

**Ouvert le 2026-09-12**, après que le propriétaire a montré que « Paiement du
personnel » n'était pas `paiement_staff.php`, alors que `FEATURES.md` ne
portait plus de ligne ouverte. Les deux affirmations étaient vraies : aucune
ligne ouverte n'a jamais voulu dire chaque page identique.

**Référence :** `Eduplateforme/ourwa_deployement/el_ourwa_CODE_v23.zip`
(8 septembre 2026), extraite dans `reference/v23/` — ignorée par git, données
réelles. Le dépôt avait été porté contre **v16** ; treize fichiers source
diffèrent entre v16 et v23 (§ Dérive), le CSS non.

**Méthode :** lire la page PHP en entier, lire la nôtre en entier, comparer
sur chaque plan — paramètres, requêtes, règles, colonnes, libellés, styles en
ligne, scripts, messages, redirections — et refaire ce qui diverge **sans rien
inventer**. Ce qui reste volontairement différent est nommé ici avec sa raison ;
tout le reste est à faire.

Légende : ✓ refaite et vérifiée au navigateur · ◐ en cours · ✗ non encore
comparée · — pas de contrepartie.

## Défauts trouvés en chemin

- **Tout le monde était déconnecté au bout de quinze minutes.** L'empreinte de
  session (0031) était celle du serveur web (« node », `localhost`), et
  `localhost` se résolvait en 127.0.0.1 ou ::1 selon le moteur : à la première
  expiration, `fingerprint_mismatch`, famille révoquée. Le serveur web
  transmet désormais `X-Client-IP` / `X-Client-User-Agent`, que l'API ne croit
  que d'un mandataire de confiance ; la boucle locale est une seule adresse.

- Après une action serveur qui redirige, `host` vaut `localhost:3000` : le
  cookie de session n'était pas trouvé. `x-forwarded-host` lu d'abord.
- Les salaires postaient leurs lignes de moyens sous `salaire`, le rapport les
  lisait sous `salaire_prof` / `salaire_staff` : jamais ventilés.
- Le formulaire de dépense n'envoyait aucun moyen de paiement ; le service les
  acceptait « en option ». Chez lui ils sont obligatoires et doivent égaler le
  montant.
